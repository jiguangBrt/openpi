# OpenPI 高质量机器人数据集采集指南

本文给出一套适用于 OpenPI 预训练、后训练和任务微调的通用采集方法。核心原则是：**先定义部署分布，再有计划地覆盖它；让场景多样，但让专家行为、数据语义和时间对齐保持一致。**

---

## 1. 先定义数据集目标

采集前先写清楚以下内容，否则“增加随机性”没有明确边界：

- **任务范围**：机器人要完成哪些任务，成功条件分别是什么。
- **部署范围**：机器人、夹爪、物体、桌面、光照、相机和初始状态会怎样变化。
- **动作约定**：关节或末端动作、绝对或增量动作、单位、维度顺序、控制频率。
- **安全边界**：允许的工作区、速度、关节限位、接触和碰撞条件。
- **评估分布**：哪些物体、场景和布局只用于测试，不进入训练集。

高质量数据不是单纯“成功率高”或“数量多”，而是同时满足：

1. 覆盖目标分布；
2. 示范动作正确且一致；
3. 图像、状态和动作同步可靠；
4. 任务、结果和采集条件可追溯；
5. 训练集与测试集不存在泄漏。

## 2. 用分层采样代替完全随机

不要随手随机摆放物体。应先列出影响任务的变量，再按区间或类别均衡采样。

| 层级 | 常见变量 |
|---|---|
| 任务 | 技能类型、任务长度、单臂/双臂、接触精度 |
| 物体 | 类别、实例、尺寸、颜色、材质、朝向 |
| 空间 | 左/中/右、近/中/远、边界区、遮挡、物体间距 |
| 场景 | 桌面、背景、光照、无关物体、相机位置 |
| 机器人 | 机型、夹爪、起始姿态、标定状态、磨损程度 |

推荐做法：

- 常见状态占主体，同时保留工作区边界、遮挡和精细接触等困难状态。
- 每个重要分层都要有足够重复，避免某些条件只有一两条轨迹。
- 排除不可达或必然碰撞的状态，除非任务明确要求识别或处理它们。
- 多任务预训练优先增加有意义的任务和场景覆盖，而不是无限重复单一任务。
- 定期统计每个任务、场景和位置分层的 episode 数，防止长尾任务被淹没。

完全随机容易产生大量相似样本，却漏掉关键边界。分层随机才能同时保证覆盖率和可分析性。

## 3. 保持专家策略一致

同一观测若经常对应互相冲突的动作，会增加策略学习难度。采集前应规定可观察、可复现的操作逻辑：

- 多个同类物体的处理顺序，例如从左到右或距目标由近到远。
- 双臂的空间分区、中央区域归属、同时到达时的优先级和等待姿态。
- 多个合法抓取点的首选规则，以及失败后的退出和重试规则。
- 任务完成后的撤离姿态和 episode 结束时机。

优先使用少量经过练习的操作者，并统一速度、抓取和路径风格。若必须由多人采集，应先用同一套示范规范校准，并按操作者统计动作速度和成功率。

对于确实需要多种解法的任务，可以保留多模态行为，但应满足至少一项：

- 不同解法由语言指令或任务标签区分；
- 每种解法都有足够、相对均衡的数据；
- 模型输入能够观察到决定解法的条件。

不要随机改变左右臂职责、物体顺序或操作风格。

## 4. 轨迹应真实、平滑、有效

示范应表现熟练操作者的真实闭环控制，而不是刻意全程匀速：

- 自由空间可以较快，接近物体、夹取、插入和放置时自然减速。
- 允许有目的的视觉或接触微调，但避免手柄抖动、反复试探和突然跳变。
- 减少无意义等待、任务完成后的多余动作和过长的前后空闲段。
- 保持加减速连续，并遵守部署时的速度、加速度和安全限制。
- 训练与部署使用相同的动作语义和控制频率；不要复制帧伪造高频数据。

轨迹过慢会让策略学会停顿，过快会增加运动模糊和接触误差。目标不是“最平滑”，而是**熟练、有效且硬件可执行**。

## 5. 正确处理失败与恢复

标准 OpenPI 行为克隆会把数据中的动作视为专家动作，不会自动判断哪一步是失误。因此：

- 普通训练集只提交满足成功标准的完整 episode。
- 夹空、碰撞、选错对象或未完成的 episode 应丢弃，但原始数据可另行归档。
- 不要把“错误动作 + 很长的补救过程”未经标注地混入核心数据集。
- 恢复行为应单独采集：从偏移、掉落、半插入等可恢复状态开始，只示范正确恢复并最终成功。
- 第一版策略部署后，可在人接管保护下采集策略真正遇到的异常状态，再迭代训练。

只有在训练方法显式使用 `success`、奖励、负例或动作掩码时，终止失败轨迹才适合进入对应训练混合物。否则，失败数据很可能教会模型重复错误。

## 6. 设计场景和视觉变化

场景变化应服务于预期泛化范围：

- 初期固定相机和基础场景，先验证机器人能学会任务。
- 流程跑通后，按采集批次改变桌面、背景、光照、物体实例和干扰物。
- 无关因素必须与任务标签、物体位置、左右臂选择和成功失败相互独立，避免视觉捷径。
- 相机位姿是高影响变量；非预期碰歪应重采，预期变化则应作为独立分层充分覆盖。
- 干扰物不应长期遮挡目标；只有部署中确实存在的困难干扰才值得加入。

每路相机都应固定牢靠、清晰对焦、曝光稳定。主视角覆盖完整工作区，腕部视角在抓取和接触阶段能看到末端与目标。一个简单检查是：**操作者只看将要提供给模型的相机画面，也能完成任务。**

## 7. 保证观测与动作数据正确

每个训练帧至少要形成一致的监督对：

```text
observation(t) = 相机图像 + 机器人状态
action(t)      = 观察该状态后实际下发的控制命令
prompt         = 当前任务的明确语言描述
```

重点检查：

- 使用单调时间戳，并保存原始采样时间，而不只保存合成的 `frame_index / fps`。
- 测量相机、状态和动作的端到端延迟，确认 `observation(t)` 没有错误配到过去或未来的动作。
- 记录实际下发命令；状态应优先使用真实反馈，而不是把命令值同时当作状态。
- 明确左右臂、关节、夹爪的顺序、单位和正负方向，训练和部署必须完全一致。
- 夹爪最好记录实际开口、力或电流反馈；仅有开合命令时，要确认视觉足以判断是否夹稳。
- 保持稳定的真实 FPS；检测重复帧、丢帧、时间跳变和数据源冻结。
- 保存相机内外参、机器人标定版本、控制器和采集代码版本。

OpenPI 自定义数据通常转换为 LeRobot 格式。至少应包含同步图像、`observation.state`、`action`、任务文本和 episode 边界，并在训练前为当前动作空间计算或正确复用归一化统计量。

## 8. 语言和任务标注

任务文本应具体、稳定，并能区分真正不同的行为：

- 使用明确动词、目标物和目标位置，避免“处理一下”“做任务”等模糊描述。
- 单任务可以先使用一个标准 prompt；需要语言泛化时，再加入少量等价改写并保持均衡。
- 不同语言描述必须与实际轨迹一致，不能为了增加文本多样性改变任务含义。
- 长任务可额外记录阶段或子任务标签，但标签边界和命名必须统一。

建议每条 episode 额外保存：

- `success`、失败类型、是否为恢复轨迹；
- `task_id`、标准 prompt、可选改写；
- `scene_id`、物体实例和初始布局分层；
- `robot_id`、操作者、采集时间和软件版本；
- episode 时长、安全事件和人工质检结果。

即使当前训练代码不使用全部字段，这些元数据也决定了后续能否可靠清洗、重采和重组训练混合物。

## 9. 每条 episode 的质量门槛

提交 episode 前至少检查：

- 任务按预先定义的成功标准完成，结果稳定可见。
- 没有危险碰撞、关节越界、夹爪异常或人为扶正目标。
- 没有缺失值、NaN、状态冻结、相机断流、长时间掉帧或明显错位。
- 图像无严重模糊、过曝、欠曝、色彩错误和关键目标遮挡。
- 动作没有非物理尖峰、遥操作抖动或异常饱和。
- 开始状态完整可见，完成后及时结束，没有大段空闲。
- prompt、任务标签、左右臂和相机名称正确。

自动校验只能发现格式和统计异常，不能替代人工回放。主采集开始前，以及每个采集批次结束后，都应随机完整回放若干 episode。

## 10. 数据集级检查与切分

训练前生成数据质量报告，至少包括：

- 每个任务、场景、物体、位置分层、机器人和操作者的数量。
- episode 时长、空闲比例、成功率和恢复轨迹比例。
- 每个状态/动作维度的最小值、最大值、均值、标准差和分位数。
- 速度、加速度、夹爪切换次数、左右臂使用比例和关节限位距离。
- FPS 抖动、丢帧、同步延迟、模糊和曝光异常。
- 重复或近重复 episode，以及极端离群轨迹。

训练、验证和测试应按场景、采集会话、物体实例、操作者或机器人整组切分，不能随机抽帧。若同一布局的相邻 episode 同时出现在训练和测试中，评估结果会严重高估泛化能力。

## 11. 推荐采集流程

1. **写规范**：定义任务、成功条件、变量分层、专家逻辑和评估集。
2. **采 pilot**：先录 20–50 条，回放并验证完整的“采集 → 转换 → 单 batch 训练 → 推理”链路。
3. **训练基线**：尽早训练小模型或短步数 checkpoint，发现字段、动作表示和视觉问题。
4. **分批扩量**：每批只引入少数新变量，并持续更新覆盖统计与质量报告。
5. **独立评估**：在留出的场景、物体和布局上做真实 rollout，而不只看训练 loss。
6. **针对性补数**：按真实失败类型增加边界状态、恢复示范或人机干预数据。
7. **冻结版本**：保存原始数据、清洗规则、排除清单、数据版本和代码提交号。

不存在适用于所有任务的固定 episode 数。应根据分层覆盖、独立真机成功率和数据规模学习曲线决定是否继续采集，而不是只追求总时长。

## 12. 采集前快速检查表

- [ ] 成功条件和 episode 结束条件已明确。
- [ ] 初始状态、物体、场景和困难状态已有分层表。
- [ ] 多物体顺序、双臂职责和多解任务的规则已统一。
- [ ] 操作者已练习，轨迹速度和动作风格一致。
- [ ] 所有相机视野、曝光、颜色、安装和标定正常。
- [ ] 状态与动作维度、顺序、单位、频率和延迟已验证。
- [ ] 丢弃失败、重录和恢复数据的规则已确定。
- [ ] 自动校验、人工回放和质量报告工具已准备。
- [ ] 训练/验证/测试按场景或会话隔离。
- [ ] 原始数据、元数据和采集代码版本可追溯。
